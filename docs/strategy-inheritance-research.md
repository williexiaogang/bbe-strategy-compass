# 不使用黑市的傳承多紅：規則與證據

查核日期：2026-10-31。目標平台：原版 Steam／PC；普通與極限分開處理。

本文件保存研究依據；後續第一版多紅試算已依其中有限案例實作，範圍見 [策略說明](strategy-reference.md)。下列資料主要來自玩家攻略與社群 Wiki，沒有取得遊戲程式或目前 Steam build 的完整規則表。網站更新日期不是遊戲版本日期。

## 結論

- 已找到逐條「傳承激活條件」表，足以開始補建傳承啟用資料。
- 有具體攻略支持延後雙端傳承的啟用，讓其與先取得的局內紅策共存。
- 不能把所有傳承一律當成佔用一般紅策槽，也不能一律免除槽位限制。
- 尚未找到可重播、標明目前版本並排除黑市的完整八紅紀錄，或無黑市全局上限的證明。先前回答「社群資料支持八紅構築」對本問題的證據不足，不能據此寫死八紅上限。

## 可先建資料的傳承啟用案例

以下以專案繁中名稱標示；均為來源 H 的候選規則，尚非本機遊戲測試結果。加號代表同時需要，「或」代表替代基礎。

| 紅策 | 傳承啟用條件 | 類型 |
|---|---|---|
| 光槍冰錐 | 技能光槍或傳承技光槍 | 單端 |
| 冰霜脈衝 | （普攻寒冷或技能寒冷）＋寒氣爆發 | 單端＋分支 |
| 黑洞減速 | 傳承技黑洞 | 單端 |
| 影子冰刺 | 衝刺影子＋召喚冰刺 | 雙端 |
| 冰擊化劍 | （普攻寒冷或技能寒冷）＋寒氣爆發＋玄冰劍刃 | 雙端＋分支 |
| 嗜血刃環 | 召喚刃環＋（普攻撕裂或技能撕裂） | 雙端 |

H 列出的「局內取得前置」不應複製成傳承啟用條件。例如啟用來源不能僅由紅策目前所在圖鑑樹推算。E 與 T3 也支持有些傳承只需相關基礎，不必重做完整合成前置；T3 使用光槍閃光舉例。

## 順序與共存：可重播的研究案例

T2 提供的測試路線：

1. 開局攜入影子冰刺，先保留召喚槽，不取得召喚冰刺。
2. 取得衝刺影子、傳承技黑洞及概率影爆需要的前置。
3. 在局內取得概率影爆。
4. 最後取得召喚冰刺，啟用影子冰刺；攻略記錄衝刺位置兩紅共存。

這是具體攻略敘述，尚未在使用者版本重播。T1 亦描述先占用一般紅策位置、後啟用雙端傳承的做法。

推導出的計算要求：只有最終配裝集合仍不夠，必須搜尋取得順序，並在每次選取策略後更新傳承啟用狀態。不能讓使用者任意延後已滿足條件的自動啟用，除非另有證據。

反向順序、同一個選取事件同時啟用多條傳承、已啟用傳承是否阻止後續所有同槽紅策，尚不可一律推定。

## 特殊槽：先列為待驗證規則

B 記錄以下額外位置：

| 位置 | 基礎 | 對應紅策候選 |
|---|---|---|
| 毒霧 | 普攻淬毒 | 寒冰毒霧 |
| 毒環 | 技能毒環 | 連續刃環 |
| 雷雲 | 電閃雷鳴 | 雷雲火彈、冰雷雲霧 |

B 另有寒冰毒霧已存在後仍取得中毒毒彈的記錄。這支持特殊槽不能直接套用每觸發位一紅，但沒有證明表中各候選都能彼此共存。

尤其不可把雷雲的兩個候選當成兩個獨立空槽，或認為三個特殊槽必能同時開滿。應檢查基礎策略互斥、前置容量及實際取得來源。

## 上限證據的修正

- T2 的早期概述稱常態最多七紅，但沒有目前版本的窮舉證明。
- T4 的九紅需要黑市；其他黑市多紅結果也不能移用到本題。
- B 關於刃系八紅及黑市補充的討論，未給出本題所需的完整無黑市取得順序，因此不能單獨證明無黑市八紅可達或為上限。

目前可支持的結論是「傳承共存可突破一般五紅模型」。八紅以及更高數量，需要具體無黑市路線與版本條件佐證。不要從帶四紅加一般五個位置直接推算九紅。

## 對原有程式的影響（實作前閱讀結果）

| 位置 | 現有簡化 | 下一步需要 |
|---|---|---|
| strategy-rules.js：inherit | 同槽傳承與局內紅策互斥 | 分開檢查開局攜入相容性、一般取得占位與後續啟用共存。 |
| strategy-rules.js：inheritanceReason | 從承載基礎與同樹 need 判定 | 改查逐條啟用條件；雙端與特定分支需分別表示。 |
| strategy-rules.js：acquireReason | 每觸發槽一紅，傳承也算占位 | 表達一般槽、特殊槽及經驗證的延後啟用例外。 |
| strategy-rules.js：fiveDualPlan／completeCharacter | 以一般五槽為完成目標 | 保留原模型作基本路線；多紅搜尋另加入來源與啟用事件，按唯一已啟用紅策名稱計數。 |

建議每條研究規則記錄：條件的 AND／OR 結構、一般取得槽、傳承啟用端、共存適用條件、來源、平台／版本、證據等級。未知與不成立須是不同狀態。

## 仍需補齊的資訊

1. 將 H 的逐條條件與現有 100 條紅策名稱對齊；搜尋未讀到的條目不能預設為單端。
2. 目前 Steam build 的傳承攜入衝突：同槽不同承載端、同一資料體攜兩紅、不同資料體攜兩紅是否規則一致。
3. 重播影子冰刺案例及反向取得順序，記錄取得提示、已啟用圖標與實際效果。
4. 逐一驗證特殊槽的普通取得與傳承啟用，不混用黑市結果。
5. 分別確認普通／極限的寒冷與史萊姆分支、III 階容量和傳承啟用要求。
6. 取得完整無黑市高紅路線：平台／build、模式、兩個資料體及各攜帶項、逐步選牌、最終已啟用列表。即使證明八紅可達，也不等於證明九紅不可能。

不必先收集傷害、掉落機率或 DPS 才能計算組合可行性；那些是後續的強度與成型機率問題。
